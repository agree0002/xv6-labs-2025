A garbage (unpredictable) value will be printed after y=.
printf's format string "x=%d y=%d" tells it to expect two integer arguments, so it reads them from registers a1 and a2 (per the RISC-V calling convention).
But the call only actually passes one argument (3), which goes into a1. Nothing is placed in a2 for the second %d.
Since printf has no way to know how many arguments were actually passed — it only trusts the format string — it goes ahead and reads a2 anyway, printing whatever value happens to be sitting there from previous computation.
